- [ ] **[HIGH]** `inert` is passed as an empty string, so React never applies it — the closed swipe drawer's Delete is still a tab stop, and every page logs a React error — `/` (pantry), and `/` (landing); repro: log in, load the pantry, and read the console, then walk the tab order; expected: `.item-card-swipe-action` is inert while closed and Tab skips it entirely; actual: React logs `Received an empty string for a boolean attribute ... inert` on every page load, and `document.querySelectorAll('[inert]').length === 0` — the attribute is never applied because React coerces `inert=""` to `false`. The drawer is therefore hidden by **`opacity: 0` alone**: measured `display:flex; visibility:visible; opacity:0; pointer-events:auto`, with all three buttons (`Use some`, `Add to shopping list`, `Delete`) at `tabIndex=0` and real geometry (Delete = 56x163 at x=802,y=296). `aria-hidden="true"` IS set, but aria-hidden does not remove anything from the tab order — it only hides it from AT, which makes this strictly worse than doing nothing: the Delete is tab stop **#12 of 60**, reached BEFORE the visible "Edit Cheddar Cheese Block" card, and because it sits inside an `aria-hidden` subtree a screen reader announces *nothing at all* when focus lands there (WCAG 4.1.2 — a focus black hole). 15 tabbable elements across the pantry (5 cards x 3 buttons) are in this state. `.focus()` on the Delete succeeds and `document.activeElement` becomes it. Mitigating detail: pointer users are safe — `elementFromPoint` at the Delete's centre returns `.item-card-qty`, so the invisible drawer does not intercept clicks. This is keyboard-only, but it is the destructive control on a card that has no delete confirmation. Fix is one character: `inert={isClosed || undefined}` / `inert={isClosed ? true : undefined}`, never `inert=""`. Evidence: console msgid=19 on `/`, msgid=4 on the landing; `{inertAttr:null, inertProp:false, ariaHidden:"true", opacity:"0", btnTabIndexes:[0,0,0]}` for all four drawers.
